# V1.4.1 设计：LLM 调用优化

> 版本：V1.4.1 | 日期：2026-08-04 | 类型：补丁版

## 1. 背景与目标

当前项目全局仅一个 LLM 模型配置项（`LLM_MODEL`），且不区分是否使用多模态能力。存在两个问题：

1. **模型能力不匹配**：部分主流 LLM（如 DeepSeek 系列）不提供多模态能力，而工作流中已有需多模态的节点（主页截图识别），未来还会新增（视频理解）。单一模型配置无法在"文本用无多模态模型、识图用多模态模型"之间灵活切换。
2. **缺少深度思考控制**：部分 OpenAI 兼容端点（Qwen/DashScope 等）支持通过 `extra_body={"enable_thinking": bool}` 开关深度思考模式，项目当前无法统一控制，无法按成本/延迟诉求关闭。

本补丁实现两个功能点，均为轻量改动、**对外 API 契约零变化**、旧 `.env` 无需改动即可运行。

## 2. 功能点一：文本模型 / 多模态模型拆分

### 2.1 配置项

- 保留 `LLM_MODEL` 语义为**文本模型**（向后兼容，现有部署 `.env` 不需改动）。
- 新增 `LLM_MULTIMODAL_MODEL`：多模态模型名。**留空时回退到文本模型**（`LLM_MODEL`）。
- 文本模型与多模态模型**共用同一 `LLM_BASE_URL` 与 `LLM_API_KEY`**（当前简化假设），仅模型名不同。

`app/config.py`：

```python
llm_model: str = "mock-model"            # 文本模型
llm_multimodal_model: str = ""           # 多模态模型；留空回退文本模型

@property
def multimodal_model(self) -> str:
    return self.llm_multimodal_model or self.llm_model
```

### 2.2 节点如何选择模型

「是否需要多模态」是节点固有属性，声明在 **Skill 配置**中，作为单一事实来源：

- `SkillConfig` 新增布尔字段 `multimodal`（读 yaml `model.multimodal`，默认 `false`）。
- `image_recognition.yaml`：`model.multimodal: true`。其余文本 Skill 保持默认 `false`。
- `LLMGateway.chat` 新增 `multimodal: bool = False` 参数：当调用方未显式指定 `model` 时，按此标志在 `settings.multimodal_model` / `settings.llm_model` 之间选择默认模型。
- 两个调用点传入 `multimodal`：
  - `SkillExecutor.run`：`multimodal=config.multimodal`。
  - `recognize_screenshot`（`app/api/agent2.py`）：`multimodal=config.multimodal`（识图 config 为 true）。

若 Skill 配置显式写了 `model.name`，仍以显式值优先（现有语义不变），`multimodal` 仅决定"留空回退时选哪个默认"。

### 2.3 image_recognition 版本号

Skill 行为（模型选择路由）变更，按 VERSIONING.md 第 4 节，`version` 升为 `"1.4.1"`。Prompt 未改，`prompt_file`/`prompt_version` 保持 `image_recognition_v2.txt` / `v2`。

## 3. 功能点二：深度思考全局开关

### 3.1 配置项

- 新增 `LLM_ENABLE_THINKING: bool`，**默认 `false`**（关闭）。
- 全局生效：关闭后工作流所有 LLM 调用均不使用深度思考。

### 3.2 实现

对齐 OpenAI SDK `extra_body={"enable_thinking": bool}` 语义——该字段合并进请求体顶层。`OpenAICompatProvider.chat` 恒定注入：

```python
payload = {"model": model, "messages": messages,
           "temperature": temperature,
           "enable_thinking": settings.llm_enable_thinking}
```

仅 `openai_compat` 路径生效；`mock` provider 不受影响。

### 3.3 兼容性提示

`enable_thinking` 是 Qwen/DashScope 等端点的扩展字段，部分严格校验未知参数的 OpenAI 兼容端点可能拒绝。默认 `false` 是安全的"不思考"路径。此提示写入 `.env.example` 与部署文档；若真实端点报错，需按该端点文档调整或后续迭代改为可选注入。

## 5. 测试策略（TDD）

- `test_config.py`：`llm_multimodal_model` 默认空、`multimodal_model` 回退文本模型、显式多模态值优先；`llm_enable_thinking` 默认 `false`。
- `test_llm_gateway.py`：`chat(multimodal=True, model=None)` 选多模态默认模型；`multimodal=False` 选文本模型；显式 `model` 时忽略标志。provider 层验证 payload 含 `enable_thinking` 且值随设置变化。
- `test_skill_executor.py`：`SkillConfig` 默认 `multimodal=False`；yaml `model.multimodal: true` 被读取。
- `test_agent2.py`：`image_recognition` config `multimodal=True`、`version=="1.4.1"`。

## 6. 非目标（YAGNI）

- 不支持文本/多模态各自独立的 base_url / api_key（当前共用）。
- 不做 per-skill 的深度思考开关（当前全局）。
- 不改任何 Prompt 内容、不改对外 API 契约、不新增依赖。
