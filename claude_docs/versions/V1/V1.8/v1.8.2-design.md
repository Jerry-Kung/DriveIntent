# V1.8.2 设计：精筛定级接口 intent_model_category 对外返回中文正式内容

> 版本：V1.8.2 | 日期：2026-08-27

## 1. 背景

V1.8.0 起对外精筛定级接口返回 `intent_model_category`，值为档位码（A/B/C/D）。
下游需要对业务对接方直接展示"东风猛士系列/越野车/25-30万SUV/其他"这类中文
档名，再自行码值→中文映射。本版本把映射收回到服务端，对外直接返回中文正式内容。

**约束**：数据库（`api_job.result` 与 `lead.intent_model_category`）仍存码值
A/B/C/D，供内部审计与统计使用——仅在对外返回时做码值→中文映射。

## 2. 改动

1. **配置**：`config/intent_categories.json`（与 `intent_categories.example.json`）
   每个档位新增 `label` 字段，存放对外中文正式内容：
   `A → 东风猛士系列`、`B → 越野车`、`C → 25-30万SUV`、`D → 其他`。
2. **模型**：`app/matching/models.py::IntentCategory` 新增 `label: str = ""`；
   缺省回退 `code` 本身，保证仅有 `rule` 的旧配置仍可按码值映射。
3. **加载**：`app/matching/loader.py` 新增 `intent_category_label_map(config)`，
   返回 `{code: label}`；未配置标准/解析失败返回空映射。
4. **对外出口**：`app/api/routes.py::get_job_status` 返回前，对 `result.results[]`
   逐条把 `intent_model_category` 码值替换为配置的 `label`；未配置标准时按码值
   原样透传（与既有的"未配置输出 null"口径解耦），null 保持不变。仅作用于
   `GET /api/v1/jobs/{job_id}` 响应副本，不改库。

## 3. 影响范围

- **对外契约变化**：`intent_model_category` 返回码值 → 中文文本。若下游此前按
  码值解析，需改为匹配中文（对接文档已更新）。
- **内部审计/统计**：`/api/leads`、线索列表页、详情页、CSV 导表、lead 服务均
  直接读库，仍返回码值 A/B/C/D，不变。
- **存储不迁移**：存量数据的库内码值不变，仅返回时按当前配置映射。

## 4. 验证

- 单测：`tests/test_api_routes.py` 新增两条——库存码值/对外中文；配置外码值
  透传、null 保持 null。
- 既有断言全部通过（query_lead_results/外行导出仍读码值，未受影响）。
