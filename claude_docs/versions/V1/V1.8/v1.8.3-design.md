# V1.8.3 设计：video_context 多车型数组化与精筛定级多意向车型口径

> 版本：V1.8.3 | 日期：2026-09-01

## 1. 背景

2026-08-31~09-01 线上频繁报 `SkillExecutionError: 4 validation errors for
VideoContextResult`：`video_context_analysis` 遇跨品牌对比类视频（多品牌多车型
同框横评）时，LLM 对 `brand`/`model`/`vehicle_category`/`powertrain` 输出数组，
而 schema 定义为单值字符串，Pydantic 校验失败，3 次重试全败后整单作业失败
（且每单额外消耗 3 次 LLM 调用）。非代码回归——该 prompt/schema 自 V1.1 未改，
系多车型视频内容与模型行为组合所致。

决策：顺应业务现实将四字段改为数组（对比类视频本就涉及多款车），并同步
确保精筛定级工作流正确处理"视频提及多款车型"的场景。

## 2. 改动

### 2.1 Schema：`VideoContextResult` 四字段数组化

- `brand`/`model`/`vehicle_category`/`powertrain`：`str | None` → `list[str] = []`，
  键名不变。
- 新增 `mode="before"` 校验器 `_coerce_to_str_list`：历史单值输出/落库数据
  归一为单元素数组，`None` 与空白串归一为 `[]`，list 透传逐元素校验，
  其余类型仍报错。新旧落库形态并存兼容，无迁移。

### 2.2 Prompt：`video_context_analysis` v1.8.3

- 四字段改数组措辞：严格依据视频内容列举所有涉及品牌/车型/品类/动力；
  单一也输出单元素数组；无法判断输出 `[]`。
- `price_range_min/max` 保持整数单值，语义改为覆盖所有涉及车型的整体售价
  区间（min 取最低、max 取最高）。
- 一带而过的竞品仍放 `competitor_models`，不计入 `model`。

### 2.3 Prompt：`comment_lead_screening` v1.8.3

- `target_brand`/`target_model` 输出说明改为：评论未指明时从视频语境品牌
  **列表**中选与该评论最相关的**一个**；必须单个字符串，禁止输出数组。
- **取舍记录**：`_ScreeningFields.target_brand/target_model` 保持 `str | None`
  严格校验，不加"取首元素"代码兜底——先以措辞防御并观测 LLM 行为；若上线后
  该字段 ValidationError 重试率上升，再打取首元素微补丁。

### 2.4 Prompt：`user_lead_analysis` v1.8.3（阶段二两处增量）

1. 意向车型识别新增禁令：视频语境（video_context）列举的品牌/车型只是
   背景信息，不得因视频提及某款车就计入 `intent_models`，严禁照抄视频全部
   车型；每款意向车型必须有该用户本人评论的意向证据支撑。
2. 多款意向车型取最优档规则补显式例子：任一款命中某高档位标准，整体即定
   该档（如一款命中"越野车"档、另一款仅最低档，则整体取"越野车"所在档位）。

排查确认（本版无需改动的部分）：多款车甄别（"提及≠意向""代询排除"）与
"逐一判档取最优档"规则 V1.8.0 已具备；`intent_models` 对外链路
（`UserLeadResult` → mapping 透传 → 出口 label 映射）本就是数组多值，
测试已覆盖。

## 3. 影响范围

- **对外契约**：无变化。video_context 不出对外 API；`intent_models`/
  `intent_model_category` 契约不变。
- **存储**：无迁移。`analysis_result.result` JSON 列新旧形态并存，下游均
  整段透传无结构化取值。
- **版本级联**：三个 skill（video_context_analysis / comment_lead_screening /
  user_lead_analysis）版本升至 1.8.3。V0 聚合路径按 `SKILL_VERSIONS` 过滤，
  升版后 1.1/1.7.2 历史语境与初筛行不再复用，存量视频在 V0 流水线下会重跑
  （历次升版既定模式）；已产出 lead 行不受影响。API 路径无历史复用问题。
- **测试**：`test_api_routes.py` 两条 label 测试改为 tmp_path 自建配置
  fixture，与未跟踪的本地实盘 `config/intent_categories.json` 解耦（该文件
  label 已漂移致断言失败）。

## 4. 验证

- 全量 355 passed（基线 347 passed + 1 failed，失败项即上述 label 测试耦合）。
- 新增用例：跨品牌数组 schema 回归（线上事故形状）、str/None 归一、
  video_context 多品牌端到端、多意向车型对外多值透传。
- 联调观察项：`VideoContextResult` 校验错误应归零；初筛 `target_brand`
  ValidationError 重试率；多车型视频下 `intent_models` 是否照抄视频全部车型。
