# V1.6.1 实现计划：analysis 字段可读性修复

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 对外 `analysis` 等面向人的文本字段不再出现内部审计字段名/枚举值/布尔字面量，仅升版定级与过滤两个 Prompt（v1.6.1），零代码逻辑变更、零契约变更。

**Architecture:** 纯 Prompt 约束方案：复制 v1.6 两个 Prompt 为 v1.6.1，重写 `analysis_text` 指令为业务化表达并新增全局可读性禁令（含正反示例）；配套升两个 yaml 与 `SKILL_VERSIONS`。设计文档：`claude_docs/versions/V1/V1.6/v1.6.1-design.md`。

**Tech Stack:** Python / Pydantic / pytest；Prompt 为 `app/skills/prompts/*.txt` 纯文本模板（`string.Template` 占位符）。

## Global Constraints

- 简体中文写文档与注释；提交信息格式沿用 `feat(v1.6.1): ...` / `docs(v1.6.1): ...`。
- 旧 Prompt 文件（`user_lead_analysis_v1.6.txt`、`user_lead_filter_v1.6.txt`）保留不动、不再被引用（VERSIONING.md 规则）。
- 对外 API 契约、DB schema、`app/api/mapping.py`、`app/skills/user_filter.py` 逻辑一律不改。
- 不新增 `inner_analysis` 等任何字段；不回填历史数据；不动 Agent1 初筛 Prompt。
- 现有测试对 v1.6 定级 Prompt 的回归锚点必须继续成立：文本中仍含 `merge_boost`、`baseline_grade`、`model_match_level`、`四段流水线`、`酌情将等级上调一级`；仍不含 `purchase_downgrade`、`不得高于 B 级`、`怂恿`、`水军`（见 `tests/test_agent2.py:79-99`）。新增的禁令反例措辞不得违反这些锚点。
- 测试命令统一 `python -m pytest`（Windows/PowerShell 环境）。
