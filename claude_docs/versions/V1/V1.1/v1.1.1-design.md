# DriveIntent V1.1.1 补丁设计：Agent1 输出字段定点优化

**日期**：2026-07-28　**类型**：补丁版本（仅调整 Agent1 对外输出契约，不改内部流水线与 Prompt）

## 1. 背景与问题

用户整体审视 V1.1 后指出 Agent1（`comment-screening`）输出存在三处不合理：

1. **`filter_type` 与 `filter_reason` 含义重复**：两者均为枚举（`filter_reason` 是 `filter_type` 的固定中文文案映射），信息完全冗余。
2. **`intent_strength` 对下游作用不大**：不应包含在 Agent1 输出中。
3. **`downgrade_applied` / `downgrade_reason` 不必单独成字段**：降级事实可由 `filter_type` 新枚举值标识，降级原因并入 `filter_reason`。

## 2. V1.1.1 契约（每条 `result.results[]` 元素）

| 字段 | 类型 | 变化 | 说明 |
|---|---|---|---|
| `comment_id` | string | 不变 | 对应输入评论 ID |
| `passed` | bool | 不变 | 是否通过初筛 |
| `filter_type` | string | **新增枚举值 `model_mismatch`** | 评论分类结果，处理失败为 `null` |
| `filter_reason` | string \| null | **由枚举文案改为纯文本补充说明** | 仅在 `filter_type` 枚举本身不足以说明时有值；当前仅 `model_mismatch` 时携带不匹配原因文本（原 `downgrade_reason` 内容） |
| `intent_strength` | — | **移除** | 内部 LLM 仍输出该字段（V0 流水线聚合依赖），仅不再对外返回 |
| `downgrade_applied` | — | **移除** | 由 `filter_type=model_mismatch` 取代 |
| `downgrade_reason` | — | **移除** | 并入 `filter_reason` |
| `analysis` / `processed_at` / `error` | | 不变 | |

`filter_type` 枚举全集与 `passed` 对应关系：

| filter_type | 含义 | passed | filter_reason |
|---|---|---|---|
| `genuine_user` | 真实普通用户 | true | null |
| `model_mismatch` | 意向车型与我方在售车型严重不匹配 | **true** | 不匹配原因文本，如"价位不匹配（…）；品类/用途不匹配（…）" |
| `existing_owner` / `ordered_owner` / `bot_spam` / `marketing_account` / `noise` / `off_topic` | 同 V1.1 | false | null（分类含义见枚举，逐条判断理由见 `analysis`） |

### 关键语义决策

- **`model_mismatch` 仍 `passed=true`**：延续 V1.1 "降级是标记而非过滤"的保守语义（LLM 对视频车型价位的估算不完全可靠），由下游自行决定如何降权处理。
- **触发条件简化**：V1.1 中 `downgrade_applied` 仅在意向强度实际下降时为 true（如原本已是 `none` 则为 false）；V1.1.1 不再依赖意向强度，只要视频语境评估出任一维度不匹配（`downgrade_levels > 0`）且评论为真实用户，即标记 `model_mismatch`。
- **优先级**：`model_mismatch` 仅施加于 `genuine_user`（异常主体/车主评论已被过滤，无降级意义），即优先级为 actor 异常类 > 车主状态 > `model_mismatch` > `genuine_user`。

## 3. 实现范围

- `app/api/schemas.py`：`ScreeningResult` 删除 `intent_strength` / `downgrade_applied` / `downgrade_reason`。
- `app/api/mapping.py`：删除 `_FILTER_REASON` 映射；`map_screening_item` 签名改为 `(item, processed_at, *, mismatch_reason=None)`，命中时合成 `filter_type="model_mismatch"` 并将原因写入 `filter_reason`。
- `app/api/agent1.py`：不再调用 `apply_downgrade` 改写 `intent_strength`；失败条目同步删除三个字段。
- `app/matching/downgrade.py`：删除 `apply_downgrade` 与 `_LADDER`（已无调用方）；`evaluate_video_context` / `DowngradeDecision` 不变。
- **不改**：`comment_lead_screening_v2.txt` Prompt、`CommentScreeningItem` 内部 schema（V0 流水线 `aggregation.py` 仍以 `intent_strength=="high"` 筛候选用户）、Agent2 全部逻辑。
- 文档：API 对接文档第 4 节、部署文档降级相关提法。
- 测试：`test_api_mapping` / `test_agent1` / `test_v11_integration` / `test_matching_downgrade` 适配。

## 4. 兼容性说明

对接方破坏性变更（补丁级但涉及字段删除，需通知对接方）：
- 依赖 `filter_reason` 固定枚举文案做分支判断的逻辑需改为依据 `filter_type`；
- 依赖 `intent_strength` / `downgrade_applied` / `downgrade_reason` 的解析需移除；
- 原 `downgrade_applied=true` 的场景现表现为 `filter_type="model_mismatch"`。
