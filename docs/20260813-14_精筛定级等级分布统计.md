## 二、数据口径说明

### 1. 数据来源

测试环境（数据库 `118.145.238.55:3306/drive_intent_backend`）近两天的 V0 流水线（`analysis_task`/`analysis_result` 表）**没有任何活动**（数据停在 2026-07-20），所有精筛定级均走**对外 API 路径**（`api_job` 表的 `profile_analysis` 任务）。

### 2. 时间窗口转换

- 库中时间字段 `finished_at` 采用 **UTC 时区**
- 北京时间窗口：`2026-08-13 00:00:00 ~ 2026-08-15 00:00:00`
- 对应 UTC 窗口：`2026-08-12 16:00:00 ~ 2026-08-14 16:00:00`（查询条件）

### 3. 等级映射规则

对外 API 结果（`api_job.result` JSON）只存储映射后的意向等级，需根据代码逻辑反推内部等级：

| 内部 lead_grade | 对外 intent_level | intent_level_code | has_value |
|----------------|------------------|-------------------|-----------|
| H              | 高               | high              | true      |
| A              | 中               | medium            | true      |
| B              | 低               | low               | true      |
| C              | -                | null              | false     |

**判定逻辑**：
- `intent_level_code` 为 `high/medium/low` → 对应 H/A/B
- `has_value=false` 或 `intent_level_code=null` → 统一记为 C

**代码依据**：`app/api/mapping.py:82-103`

```python
_GRADE_MAP = {
    "H": ("高", "high", 92, 85),
    "A": ("中", "medium", 77, 70),
    "B": ("低", "low", 60, 50),
}

def map_profile_result(out: UserLeadResult, ...):
    mapped = _GRADE_MAP.get(out.lead_grade)
    has_value = bool(has_comments and out.is_valid_lead and mapped is not None)
    if not has_value:
        return ProfileResult(..., has_value=False, intent_level=None, ...)
    level, code, base, floor = mapped
    return ProfileResult(..., intent_level=level, intent_level_code=code, ...)
```

### 4. C 级细分说明

窗口内所有 10,383 个 C 级账号**均带有分析文本**（`analysis` 字段非空），即都是实际走完了以下流程判出的 C：

1. V1.6 无效用户过滤节点（`user_filter`）→ 命中六类规则直接判 C
2. 未被过滤的账号 → 经 `user_lead_analysis` 定级 → 初判 C
3. 经 `user_review` 复核 → 维持或降为 C
4. 经 `analysis_polish` 润色对外叙述

**不存在**"无评论直接置 C"的空壳记录（对外接口会拦截 `len(comment_history)==0` 的账号，直接返回 `has_value=false` 而不调用 LLM）。

## 三、统计方法与 SQL 脚本

### 环境依赖

- Python 3.14.5
- pymysql 1.1+
- 数据库连接：`charset='utf8mb4', use_unicode=True`

### 核心统计脚本

```python
import pymysql
import json
from collections import Counter

# 1. 连接测试环境数据库
conn = pymysql.connect(
    host='118.145.238.55',
    port=3306,
    user='driveintent',
    password='Huawei12!@',
    database='drive_intent_backend',
    charset='utf8mb4',
    use_unicode=True
)
cur = conn.cursor()

# 2. 查询窗口内的 profile_analysis 任务
sql = """
SELECT id, status, result 
FROM api_job
WHERE job_type='profile_analysis'
  AND finished_at >= '2026-08-12 16:00:00' 
  AND finished_at < '2026-08-14 16:00:00'
  AND result IS NOT NULL
"""
cur.execute(sql)

# 3. 解析 result JSON，统计等级分布
grade_counter = Counter()
err_count = 0
acct_total = 0
bad_jobs = 0
code2grade = {'high': 'H', 'medium': 'A', 'low': 'B'}

while True:
    rows = cur.fetchmany(50)
    if not rows:
        break
    for jid, status, res in rows:
        try:
            data = json.loads(res)
        except Exception:
            bad_jobs += 1
            continue
        
        for acct in data.get('results', []):
            acct_total += 1
            if acct.get('error'):
                err_count += 1
                continue
            
            code = acct.get('intent_level_code')
            if code in code2grade:
                grade_counter[code2grade[code]] += 1
            else:
                grade_counter['C'] += 1

conn.close()

# 4. 输出统计结果
ok = sum(grade_counter.values())
for g in ['H', 'A', 'B', 'C']:
    n = grade_counter[g]
    print(f'{g}: {n}  ({n/ok*100:.2f}% of graded, {n/acct_total*100:.2f}% of all)')
```

## 四、业务分析

### 1. 漏斗型分布符合预期

从评论初筛 → 用户精筛定级的天然漏斗：
- **70% C 级**：无效用户过滤 + 无明确购车意向 + 弱信号用户
- **22% B 级**：浅层意向，需长期孵化
- **7% A 级**：中等意向，短期转化可能性较高
- **0.3% H 级**：高价值线索，强意向 + 明确需求 + 短期购车计划

### 2. V1.6 过滤节点生效

从 LLM 调用量差异（`user_lead_filter` 15,204 次 vs `user_lead_review` 8,814 次）推测：
- 约 **42%** 的账号在过滤节点被拦截（命中"已购车/推广账号/营销号/无关用户/空洞评论/低质用户"六类规则）
- 这部分账号直接判 C，未进入定级 → 复核 → 润色流程，节约了约 6,000+ 次 LLM 调用

### 3. 复核节点改级率

`user_lead_analysis` 15,077 次，`user_lead_review` 8,814 次（约 58% 进入复核）：
- 未被过滤的账号才进复核，符合设计预期（V1.6.2 引入）
- 复核节点的具体改级方向（升级/降级/维持）需结合 `llm_call_log.output_text` 进一步解析

### 4. 对比历史趋势

由于 V0 流水线数据停在 7 月 20 日，无法直接对比历史分布。建议：
- 后续同口径统计 7 月下旬数据（若 API 任务覆盖该时段）
- 或待 V0 流水线恢复后，对比同版本（V1.6.4）下两种路径的等级分布差异
